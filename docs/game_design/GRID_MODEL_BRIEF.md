# 격자 모델 두 안 — 3×3 영웅 / 4×4 포커

> **상태: 결정됨 — 3×3 종족×직업.** 결론과 이유는 [GRID_MODEL_OPTIONS.md](GRID_MODEL_OPTIONS.md) 맨 위에, 확정 내용은 [GAME_DESIGN.md](GAME_DESIGN.md)에 있다.
> 아래는 결정 전에 두 안을 나란히 놓고 본 요약이다. 기록으로만 남긴다.

## 양쪽이 공유하는 것

모델 선택과 무관하게 게임의 뼈대는 같다.

- 왼쪽 격자에 영웅을 배치하고, 오른쪽에서 몬스터가 성벽을 향해 전진한다
- **성벽이 무너지기 전에 몬스터를 잡으면 승리.** 제한시간이 몬스터의 위치와 성벽 HP로 표현된다
- 몬스터는 영웅을 공격하지 않는다. 영웅은 죽지 않고, 몬스터의 목표는 성벽뿐이다
- 전투는 자동 진행되고 플레이어 개입이 없다. 플레이어가 하는 일은 **배치와 구매 판단**이다
- 배치 → 전투 → 상점 → 다음 라운드. 성벽 HP는 라운드 사이에 이월된다
- 전역 규칙을 바꾸는 **전술카드**를 런 중에 모은다

## 갈리는 지점

> **영웅의 정체성이 개체에 있느냐, 속성에 있느냐.**

두 모델은 공존이 어렵다. 한쪽이 커지면 다른 쪽이 노이즈가 되기 때문이다.

## 3×3 영웅안

**영웅은 고유한 개체다.** 저마다 패시브를 갖고, 아이템을 끼고, 역할이 있다. 인접한 칸끼리 관계가 생긴다.

**배치의 성격이 조건부다.** 평소에는 결과를 약간 밀어주는 정도지만, 배치를 참조하는 전술카드를 잡으면 그 런에서는 배치가 핵심이 된다. 어떤 런이 배치 런인지가 런마다 정해진다.

**강점**

- **첫인상이 자기 게임으로 읽힌다.** 영웅 격자 + 성벽은 스크린샷에서 고유해 보인다. 단 이건 겉모습이지 구조가 아니다 — 반격 없는 적과 이월되는 방어선은 타워디펜스의 장르 표준이라 차별화 근거로 쓸 수 없다
- **영웅에 애착이 생긴다.** 키우고 아이템을 붙이는 육성의 재미가 그대로 작동한다
- 현재까지의 설계가 거의 그대로 살아남는다

**약점**

- **만들 것이 많다.** 영웅과 시너지를 계속 추가해야 하고, 출시 후에도 그 압력이 이어진다
- **밸런싱을 자동화하기 어렵다.** 조합이 얽혀 있어 검증을 사람 손으로 해야 한다
- 배치 최적해가 고정되면 지루해질 수 있다 — 전술카드가 이를 방어하는 구조다

## 4×4 포커안

**영웅은 속성 조합이다.** 카드가 곧 영웅이고, 랭크와 무늬의 곱으로 종류가 나온다. 배치한 행과 열이 각각 포커 핸드로 평가되며, 모든 칸이 행 하나와 열 하나에 동시에 걸린다.

**배치가 항상 핵심이다.** 한 장을 옮기면 두 줄이 같이 바뀌므로, 모든 줄을 동시에 만족시킬 수 없는 데서 판단이 생긴다.

**강점**

- **포커 핸드가 파티 편성 철학으로 번역된다.** 포카드는 한 직업 특화, 플러시는 한 방향 몰빵, 스트레이트는 균형 편성. 기성 문법을 빌리므로 설명이 거의 필요 없다
- **만들 것이 적다.** 랭크 목록과 무늬 목록만 설계하면 조합으로 종류가 나온다. 스프라이트도 진영 × 역할로 덮인다
- **밸런싱을 자동 검증할 수 있다.** 배치가 수식으로 환원되므로 시뮬레이션이 최적 배치를 대신 찾아준다
- 매 판 다른 패가 오므로 배치 문제가 매번 새로 생긴다

**약점**

- **기존 포커 로그라이크의 아류로 읽힐 위험**이 있다. 스토어 페이지 스크린샷에는 배치가 보이지 않는다
- **영웅에 애착이 생기지 않는다.** 카드가 개성을 가지면 조합 규칙이 마비되므로, 개성을 얇게 유지해야 한다
- 격자 크기를 늘리는 성장축을 쓸 수 없다 — 줄이 짧아지면 핸드가 성립하지 않는다
- 행과 열을 동시에 보는 것이 깊이가 아니라 마비로 느껴질 수 있다

## 한눈에

| | 3×3 영웅 | 4×4 포커 |
|---|---|---|
| 영웅의 정체성 | **개체** — 고유 패시브·아이템 | 속성 조합 — 랭크 × 무늬 |
| 배치의 비중 | 조건부 — 전술카드에 따라 커진다 | **항상 핵심** |
| 차별화 | 겉모습은 고유 — 구조는 장르 표준 | 구조는 고유 — 겉모습이 아류로 읽힐 위험 |
| 만들 분량 | 많음 — 계속 추가해야 함 | **적음 — 한 번 만들면 닫힘** |
| 밸런싱 | 사람 손 | **자동 검증 가능** |
| 애착 | **생김** | 원리적으로 어려움 |
| 성장축 | 칸 해금 · 영웅 육성 · 카드 | 카드 · 랭크 조정 (칸 해금 불가) |
| 반복 플레이 | 전술카드가 변주를 공급 | **패가 매번 달라 자동 확보** |

## 어떻게 정할 것인가

머리로는 판단이 서지 않아 **프로토타입 두 개를 따로 돌려 비교한다.** 몬스터와 성벽 조건을 같게 맞춰, **성벽 잔여 %** 라는 같은 자로 잰다.

두 프로토 모두 같은 질문에 답한다 — **배치가 결과를 유의미하게 바꾸는가, 그리고 그게 화면에서 읽히는가.**

검증되지 않은 것 위에 검증되지 않은 것을 쌓지 않는다. 각각 따로 확인한 뒤에 합칠지 정한다.

## 현재 미결

- 두 모델 중 어느 쪽으로 갈지 — **이 문서의 주제**
- 포커안을 택할 경우, 랭크와 직업의 관계 및 무늬에 실을 내용
- 전술카드가 배치에 거는 방식
- 영웅 · 아이템 · 전술카드 세 층을 모두 유지할지, 줄일지
