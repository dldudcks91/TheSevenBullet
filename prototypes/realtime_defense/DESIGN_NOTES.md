# PROTOTYPE — realtime_defense

> **PROTOTYPE - NOT FOR PRODUCTION.** 버리는 코드다. `src/`에서 이 폴더를 import하지 않는다.
> Date: 2026-08-05 · 기준: [GAME_DESIGN.md](../../docs/game_design/GAME_DESIGN.md) (실시간 로그라이크 TD 확정본)
>
> 앞선 두 프로토는 현재 설계와 어긋난다. `grid_wall_defense`는 턴제 배치 검증(칸당 1명),
> `poker_grid`는 기각된 모델이다. 이 프로토가 현재 설계의 프로토다.

## 핵심 질문

> **흐르는 시간 속에서 구매·배치·아이템 발동 판단이 실제로 성립하는가?**

라운드도 정비 단계도 없다는 것이 이 설계의 근본 전제다. 여기서 "정신없어서 아무 판단도 못 한다"가
나오면 상점·문턱·겹침 설계 전부가 무의미하다. 부수 측정 두 가지를 같이 태웠다 — 킬 속도가 실제로
여유 시간으로 환산되는가(B), 문턱 통함·막힘 표시가 구매 판단을 바꾸는가(C).

## 실행

Godot 4로 `TheSevenBullet` 폴더를 연다. `project.godot`의 `run/main_scene`은 이 프로토를 가리키게
바꿔 두었다. F5.

**화면:** 왼쪽부터 **3×3 격자 → 성벽 → 보스 레인**(오른쪽 끝에서 걸어온다). 하단은 **5슬롯 매대 ·
리롤 · 성벽 패널 · 측정 패널**. 상단은 골드·성벽·처치·다음 스폰·**대기열**.

| 조작 | |
|---|---|
| 카드 → 칸으로 드래그 | 구매 (결제는 드롭 순간) |
| 아이템 카드 → 부대 위로 드래그 | 장착 |
| 배치된 부대끼리 드래그 | 자리 교체 (즉시·무료) |
| 부대 클릭 / `[1]`~`[9]` | 아이템 발동 |
| 호버 | 카드·부대 상세 |
| `[Space]` | 일시정지 — **정지 중 모든 입력 차단** (설계 규칙 그대로) |
| `[S]` | 스폰 모드 전환 (고정 스케줄 ↔ 킬 연동) |
| `[Z][X][C]` | 1x / 2x / 4x · `[R]` 재시작 |

## 만든 것

- **무정지 실시간.** 라운드 없음. 보스가 스케줄대로 계속 오고, 그 위에서 전부를 판단한다
- **한 칸 = 한 부대.** 티어가 인원과 개체 크기를 정한다(6명/4명/3명/2명/1명, 스프라이트 스케일 연동)
- **주기와 인원의 직교.** 칸 공격력을 인원이 나눠 **타격당 딜**을 만들고, 총 화력은 직업의 주기가 정한다
- **문턱은 이진이다.** 타격당 딜이 보스의 방어력(물리)/마법저항(마법)을 **넘으면 감쇄 없이 전부, 못
  넘으면 8%만.** 단순 감쇄면 모든 보스가 "체력 많은 놈"으로 수렴하고, 완전 면역이면 손에 답이
  없을 때 그냥 진다
- **통함/막힘 사전 표시.** 배치된 부대와 매대의 병사카드에 현재 타겟 기준으로 표시. 칸에는
  `5.0→20`(타격당 딜 → 문턱) 수치도 같이
- **직업 4종** — 전사(물리·표준) / 궁수(물리·빠름) / 마법사(마법·최느림) / 사제(비공격·인접 고정값 버프)
- **아이템 = 동사 3종** — 충격 망치(밀어내기) · 서리 족쇄(둔화) · 화염 낙인(화상, **문턱 무시**).
  쿨다운을 초가 아니라 **몸의 박자 수**로 채워서, 같은 아이템도 빠른 부대에선 잦고 작게,
  소수정예에선 드물고 크게 나간다. 효과량은 타격당 딜에 비례
- **보스 아키타입 5종** — 돌격형·장갑형·주술형·재생형·거물. 12마리 유한 런, 4마리마다 거물
- **최근접 타게팅** + **겹침**(앞 보스가 살아 있어도 다음이 온다) + **밀어내기 저항의 시간 상승**
- **5슬롯 매대** — 첫 매대는 병사카드로만, 킬하면 무료 갱신 + 리롤가 원가 복귀, 구매한 슬롯은
  다음 갱신까지 빈 채, 리롤은 연속마다 비싸짐
- **성벽** — 런 전체를 관통하는 단일 지속 자원. 매대 밖 고정 패널에서 수리(현재)/최대HP 업그레이드(미래)
- **대기열 노출** — 다음에 올 보스 6마리와 남은 시간이 상단에 보인다
- **칸별 기여도** — 누적 딜과 비율 막대

## 의도적으로 뺀 것

전술카드 · 종족 시너지 · 리더 · **기사**(보스 디버프가 없으니 수호 오라의 존재 이유가 없다) ·
보스의 병력 디버프 · 구간 연출 · 언락 · 밸런싱

> 디버프를 뺐으므로 **"인원이 디버프 완충재"** 축은 이 프로토가 검증하지 않는다. 인원이 하는 일
> 셋 중 둘(타격 쪼개기, 고정값 증폭)만 걸려 있다.

## 취한 단축

- 수치 전부 하드코딩. `src/data/`로 옮기지 않는다
- 에러 처리 없음. 스프라이트 로딩은 `grid_wall_defense`의 것을 다시 줄여 베낌(import 금지, 복사만)
- 재배치를 **즉시·무료**로 뒀다 — 「미결」의 한쪽 극단이다. 제약을 두는 쪽은 안 만져봤다
- 골드는 킬 보상만. 겹쳐서 잡은 보스도 동일 지급(일부러 겹치게 하는 전략이 생기는지 관찰용)

## 스폰 모드 두 가지 — 「미결」 1순위를 직접 태운 것

「미결」의 *"강하면 다음 스폰까지 멍하니 기다리고, 킬 즉시 스폰이면 숨 돌릴 틈이 없다"* 를 앉아서
고르지 않고 `[S]`로 갈아 끼우며 비교하게 했다.

| 모드 | 규칙 |
|---|---|
| **고정 스케줄** | 스폰 시각이 절대적. 빨리 잡으면 그만큼 온전히 논다 |
| **킬 연동** | 킬하면 3.5초 뒤 다음 한 마리를 당겨온다. 스케줄은 상한으로만 남아 안 죽여도 결국 온다 |

## 헤드리스 검증

`_smoke.gd`는 무입력 실행으로는 안 타는 경로(드래그 구매·자리 교체·아이템 발동·패널 구매·무효
드롭)를 강제로 태우는 임시 봇이다. 고정 편성으로 끝까지 돌린다.

```
godot --path . --headless --fixed-fps 60 --script prototypes/realtime_defense/_smoke.gd
godot --path . --headless --fixed-fps 60 --script prototypes/realtime_defense/_smoke.gd -- adaptive
godot --path . --fixed-fps 60 --script prototypes/realtime_defense/_smoke.gd -- shots=<폴더>   # 스크린샷
```

**여기서 실제로 잡은 버그 하나** — 킬 연동 모드에서 킬 한 번이 *남은 보스 전부*를 즉시 스폰시켰다
(겹침 11마리). 킬이 당기는 몫은 한 마리뿐이어야 해서, 당김 시각을 스폰 때 소모하도록 고쳤다.

**봇 실행 결과 (사람 손이 아니라 고정 9칸 편성, 중간 구매 없음 — 밸런스 판정이 아니라 기전 확인용):**

| | 고정 스케줄 | 킬 연동 |
|---|---|---|
| 결과 | 패배 (10/12, 163.8s) | 클리어 (12/12, 192.5s) |
| 평균 처치 소요 | 12.9s | 13.0s |
| 최대 겹침 | 3마리 | 2마리 |
| 막힌 타격 비율 | 81% | 85% |

같은 편성인데 고정 스케줄에서만 무너진다 — 킬이 느려지면 스케줄이 그냥 다음 놈을 얹어서 눈덩이가
된다는 것, 즉 **"제한시간 대신 감당할 것이 하나 는다"가 기전 수준에서는 작동한다**는 뜻이다.

**다만 막힌 타격 비율 80%대가 눈에 걸린다.** 봇은 중간에 편성을 안 바꾸므로 저티어가 그대로 남아
그런 것이지만, 문턱이 지배적이면 "저티어 다수는 잘게 쪼개져 막힌다"가 트레이드오프가 아니라
**저티어 전면 무효화**가 된다. 사람이 플레이하며 교체로 해소되는지가 이 프로토의 실제 관전 포인트다.

## 확인해볼 것

| | 무엇을 보는가 |
|---|---|
| 첫 보스 두세 마리 | 전투를 보면서 카드를 읽고 살 수 있는가, 아니면 화면 하나를 포기하게 되는가 |
| 킬 직후 | 매대 갱신을 **알아채는가**. 갱신이 보상으로 느껴지는가 |
| 겹쳤을 때 | 두 마리가 되면 회복하려 드는가, 그냥 포기하게 되는가 |
| 막힘 표시 | 표시를 보고 구매를 실제로 바꾸는가, 아니면 그냥 비싼 걸 사는가 |
| 아이템 발동 | 발동 시점을 고르는가, 아니면 준비되는 대로 누르게 되는가 (후자면 액티브일 이유가 없다) |
| 성벽 패널 | 카드와 수리 사이에서 갈등이 생기는가 |
| `[S]` 두 모드 | 어느 쪽이 "킬 속도가 여유를 산다"로 느껴지는가 |

**핵심 체크:** 위의 어느 하나라도 "볼 틈이 없다"로 답이 나오면 실시간 전제가 흔들린다. 그때
고칠 곳은 UI가 아니라 **스폰 스케줄**이다.
