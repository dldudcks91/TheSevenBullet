> 이 skill은 **전투 데이터(유닛/스킬/시너지)** 의 사후·사전 검증을 담당한다.
> 경제·카드 가격은 `balance-check` 의 `economy` 도메인이 담당하므로 여기서는 다루지 않는다.
> 설계 단계의 공식 정의는 `systems-designer` 에이전트, 사후 데이터 이상값은 `balance-check` 가 책임지고,
> 본 skill은 **그 둘 사이의 "튜닝 루프"** 를 책임진다.

---

## 0. 사용 시점

다음 중 하나라도 해당하면 즉시 실행한다.

- `src/data/units/units.csv` 또는 적/스킬/시너지 데이터를 수정한 직후
- 신규 유닛/스킬을 추가했을 때
- 특정 라운드/웨이브 클리어율이 의도와 다르다는 피드백을 받았을 때
- "이 카드만 있으면 항상 이긴다 / 이 카드는 절대 안 뽑는다" 류 보고가 왔을 때

## Phase 1: 변경 범위 파악

`$ARGUMENTS[0]` 해석:

- **유닛 id** (`soldier`, `werebear` 등) → 해당 유닛 단일 튜닝 모드
- **CSV 경로** → 파일 전체를 변경된 항목으로 간주
- **변경요약 텍스트** → 사용자에게 무엇이 바뀌었는지 한 번 더 확인
- 인자 없으면 `git diff src/data/` 로 무엇이 바뀌었는지 추론, 모호하면 사용자에게 질문

수집해야 할 정보:

1. **변경 대상**: 어느 유닛/스킬/시너지가
2. **변경 내용**: 어떤 스탯이 (HP/ATK/SPD/RANGE/DEF/COST)
3. **변경 의도**: 왜 (강화? 너프? 역할 재정의?)
4. **영향 범위**: 다른 시스템에 파급되는가 (시너지 브레이크포인트, 코스트 한도, 웨이브 의도)

## Phase 3: 이론값 검증 (Power Score)

`ref_unit_balancing_process.md` 의 공식을 그대로 적용한다.

```
DPS   = ATK / attack_speed       (attack_speed = 공격 1회 주기, 초)
EHP   = HP × (1 + DEF × k_arm)   (k_arm = 0.10 잠정)
POWER = DPS × EHP × ROLE_MULT
```

**ROLE_MULT 가이드** (현 잠정값 — 미정이면 사용자에게 확인):

| 특성 | 배수 |
|---|---|
| 원거리 (`is_ranged=true`) | ×1.20 |
| 고기동 (`move_speed ≥ 150`) | ×1.15 |
| 부활/사망 강화 | ×1.30 |
| 공격력 디버프 | ×1.20 |
| 분열·소환 | ×1.30 |
| 미니보스 | ×1.40 |
| 보스 | ×1.80 |

기준 유닛: **`orc` = POWER 1.0** (변경 시 사용자 합의 필수).

### 검증 출력

| 유닛 | 변경 전 POWER | 변경 후 POWER | 의도 곡선 위치 | 판정 |
|---|---|---|---|---|
| soldier | 0.92 | 1.05 | W1 기준선 ±10% | ✅ 정상 |
| werebear | 5.80 | 7.20 | W10 미니보스 (목표 5.5) | ⚠ 과강화 |

판정 기준:
- ✅ **정상**: 의도 곡선 ±15% 이내
- ⚠ **경계**: ±15~30%
- ❌ **이상**: ±30% 초과 — 즉시 재조정 권고

## Phase 4: 매치업 시뮬레이션

이론값만으로는 AI 패턴·스킬 발동 타이밍·집중공격 같은 emergent 효과를 못 잡는다.
실제 전투 결과를 봐야 한다.

### 4-A: 시뮬레이터 가용성 체크

```bash
# 헤드리스 배치 시뮬레이터가 있는지 확인
ls src/tools/sim_runner.gd 2>/dev/null
```

**있으면** → Phase 4-B (자동 모드)
**없으면** → Phase 4-C (수동 추정 모드) + 인프라 구축 권고

### 4-B: 자동 모드 (시뮬레이터 있음)

표준 매치업 셋:

1. **거울전 (Mirror)** — 같은 유닛 5v5. 결정론 검증 + tie 비율 체크
2. **기준전 (Vanilla)** — 변경 유닛 N개 vs `orc` 동수. 가장 직관적 power 비교
3. **카운터 (Counter)** — 변경 유닛이 카운터당해야 하는 타입 vs 변경 유닛
4. **웨이브 핏 (Wave Fit)** — 변경 유닛 단독 편성 vs 의도 웨이브의 실제 적 라인업

각 매치업 N=200 회 (시드 다르게) 실행, 다음을 추출:

- **승률** — 50%가 균형, 30~70% 밖이면 이상
- **TTK** — 평균/p10/p90 (median이 의도와 맞는가)
- **TTD** — 우리 유닛이 죽기까지 평균 시간
- **잔존율** — 승리 시 평균 생존 유닛 수 (압승/신승 구분)

### 4-C: 수동 추정 모드 (시뮬레이터 없음)

이론값으로 1v1 TTK를 손계산:

```
TTK(A→B) = EHP(B) / DPS(A)        (A가 B를 처치하는 데 필요한 초)
승자 = TTK 더 짧은 쪽
잔존 HP비율 = 1 - TTK_winner / TTK_loser
```

핵심 매치업 5~10개를 표로 정리하여 사용자에게 제시.

> 이 모드의 한계: 사거리/이동/스킬 발동/집중공격을 무시한다.
> 결과를 절대값이 아닌 **상대 비교**로만 사용하고, 시뮬레이터 구축을 권고한다.

## Phase 5: 이상 패턴 탐지

다음 패턴을 의도적으로 찾는다 (없을 수 있지만 항상 체크).

### 5-A: 지배 전략 (Dominant)

> "코스트 동일/비슷한데 모든 매치업에서 우월" → 지배 전략.
> 다른 모든 카드를 dominated로 만든다 (= 죽은 카드 양산).

체크 방법: 같은 코스트 유닛들끼리 매치업 + 웨이브 핏을 비교, 항상 1등인 유닛이 있는지.

### 5-B: 죽은 카드 (Dead Card)

> "어느 매치업에서도 평균 이하, 어느 웨이브에서도 1순위가 아님" → 픽 안 됨.
> 코스트 대비 효율이 평균보다 20% 이상 낮으면 후보.

### 5-C: 깨진 카운터 (Broken Counter)

> 의도된 카운터 관계가 작동 안 함.
> 예: archer가 orc를 카운터해야 하는데 1v1에서 50% 미만이면 의도 어긋남.

### 5-D: 시너지 절벽 (Synergy Cliff)

> 시너지 브레이크포인트 직전/직후 power 차이가 비정상적으로 큼.
> 2개 발동에서 4개로 갈 때 power가 ×1.2 정도가 적정 — ×2.0이면 4개 강제 → 자유도 상실.

## Phase 6: 튜닝 권장안

> **원칙: 큰 노브부터, 작은 노브는 마지막.**
> Mechabellum 패치 패턴: `cost↑ + 효과↓` 같이 묶어 정밀 너프, raw HP/ATK는 마지막에 ±5~10% 단위.

권장 순서:

1. **ROLE_MULT 조정** — 역할 재정의급 변경 (예: 원거리 ×1.2 → ×1.15)
2. **archetype 비율 조정** — tank/dps/range 매트릭스의 분배 비율
3. **cost 조정** — 강함/약함을 가격으로 흡수
4. **스킬 효과 조정** — 발동 조건/수치
5. **raw HP/ATK** — ±10% 이내 미세조정 (마지막 수단)

**금지 패턴**:

- raw 값 ±5% 이하 미세조정으로 시작 — 의미 없음, 시간 낭비
- 한 패치에 5개 이상 동시 변경 — 무엇이 효과 있었는지 분리 불가
- "감"으로 결정 — Phase 3~5 데이터 없는 권장은 출력하지 않는다

## 출력 톤·금지

- **반드시 데이터 기반**: 추측·경험칙 단독 결론 금지. 모든 판정 옆에 출처(이론값/시뮬결과/문서참조) 명시
- **수치는 CSV에서 직접 읽는다** — 기억·과거 대화에 의존 금지
- **금지**: 본 skill에서 시너지 시스템 *설계* (기획자/systems-designer 영역). 본 skill은 *튜닝*만 담당
- **금지**: 코드 변경 (battle_simulator, unit.gd 등) — 데이터(CSV·json)만 만진다
- 사용자가 "그냥 너프해줘" 같은 모호한 요청을 해도 Phase 1~5 없이 바로 수치를 바꾸지 않는다
