# PROTOTYPE — grid_wall_defense

> **PROTOTYPE - NOT FOR PRODUCTION.** 버리는 코드다. `src/`에서 이 폴더를 import하지 않는다.
> Date: 2026-08-03

## 핵심 질문

> **9명을 3×3 어디에 놓느냐가 결과를 유의미하게 바꾸는가? 그리고 그게 화면에서 읽히는가?**

상점·런 구조·전술카드·아이템은 전부 표준이라 앉아서 따져도 답이 나온다. 만져봐야 아는 건 배치뿐이고, 여기서 안 되면 나머지가 무의미하다.

## 실행

Godot 4로 `TheSevenBullet` 폴더를 연다. 메인 씬이 `poker_grid`로 바뀌어 있으면
`project.godot`의 `run/main_scene`을 `res://prototypes/grid_wall_defense/proto.tscn`으로 되돌린다. F5.

**화면 배치:** 왼쪽부터 **병력(3×3) → 성벽 → 몬스터 진입로**. 성벽은 병력 오른쪽 타격 지점에 서고,
몬스터는 오른쪽에서 걸어와 성벽 앞에서 멈춰 성벽을 때린다. 성벽은 위에서부터 무너진다.

- 하단 트레이에서 영웅 클릭 → 격자 칸 클릭해서 배치 (같은 영웅 중복 가능)
- 배치된 영웅 클릭 → 제거
- **전투 시작** → 자동 진행. `[1] [2] [3]` 키로 1x / 2x / 4x
- 결과 후 **다시 배치** → 몬스터는 매번 동일하므로 배치만 바꿔 비교한다

## 측정 방식

**성벽 잔여 %** 가 점수다. 몬스터가 고정이므로 이 숫자 하나로 배치를 직접 비교할 수 있다.
지면 "몬스터 잔여 %"가 나와서 얼마나 모자랐는지 보인다.

## 만든 것

- 3×3 배치 + **상하좌우 4방향 인접** 버프 (칸에 표시된 숫자 = 인접 칸 수. 중앙 4 / 변 3 / 모서리 2)
- 영웅 6종 — 숫자가 아니라 **구조**로 다르게:

  | 영웅 | 성격 | 기본 DPS |
  |---|---|---|
  | 전사 | 기준선 | 12.0 |
  | 궁수 | 속사 (딜 작고 잦음) | 12.5 |
  | 마법사 | 버스트 (느리고 큼) | 15.0 |
  | 광전사 | 램프 (칠수록 누적 상승) | 9.6 → 상승 |
  | 성직자 | 인접 **공격력 +4 (고정)** | — |
  | 음유시인 | 인접 **공속 +0.35 (고정)** | — |

- 몬스터 1마리 — 우측에서 전진 → 타격 지점 도달(약 10초) → 성벽을 주기적으로 타격
- 성벽 HP. 0이 되면 패배

## 설계 의도 — 왜 버프를 "고정값"으로 줬나

퍼센트 버프는 **누구에게 붙여도 이득이 같다.** 그러면 배치가 결정이 아니다.
고정값이면 비대칭이 생긴다:

- **성직자(공격력 +4)** → 자주 때리는 쪽이 이득이 큼. 궁수 옆이 정답
- **음유시인(공속 +0.35)** → 한방 큰 쪽이 이득이 큼. 마법사 옆이 정답

여기에 인접 칸 수 기울기(중앙 4 / 모서리 2)가 곱해지면서 "버퍼를 어디 세울까"가 판단이 된다.

## 확인해볼 배치 (예상치)

| 배치 | 예상 |
|---|---|
| 전사 9명 | **패배** — 아슬아슬하게 모자람 (기준선) |
| 궁수 5(모서리+중앙) + 성직자 4(변) | 승리, 성벽 60%대 |
| 마법사 5 + 음유시인 4 | 승리, 성벽 70%대 |
| **마법사 5 + 성직자 4** (짝 잘못) | **패배** — 궁합이 틀리면 벌받는지 |
| 버퍼를 모서리에만 | 위보다 나빠야 함 — 인접 수가 결정에 실제로 걸리는지 |

**핵심 체크:** 위 배치들이 성벽 잔여 %에서 **눈에 띄게 갈리는가.** 다 비슷하면 배치는 장식이고 설계를 다시 봐야 한다.
