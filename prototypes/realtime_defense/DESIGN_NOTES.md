## 핵심 질문

> **체급 3단과 병사카드 합류제 위에서, 흐르는 시간 속의 구매·배치 판단이 성립하는가?**

라운드도 정비 단계도 없다는 것이 이 설계의 근본 전제다. 여기서 "정신없어서 아무 판단도 못 한다"가
나오면 상점·전투·겹침 설계 전부가 무의미하다. 부수 측정 셋을 같이 태웠다 — 킬 속도가 실제로
여유 시간으로 환산되는가(B), **감산·비율 두 공식이 "보스마다 답이 갈린다"를 실제로 만드는가**(C),
**부대를 채워가는 성장이 "9번 사면 끝"을 대체하는가**(D).

## 실행

Godot 4로 `TheSevenBullet` 폴더를 연다. `project.godot`의 `run/main_scene`은 이 프로토를 가리키게
바꿔 두었다. F5.

**화면:** 왼쪽부터 **3×3 격자 → 성벽 → 보스 레인**(오른쪽 끝에서 걸어온다). 오른쪽 위 구석에
**예고 슬롯**. 하단 밴드는 왼쪽부터 **리롤 · 5슬롯 매대 · 보유 슬롯 블록**(유물 5 + 전술 5,
정사각 80px 아이콘). **상세 카드는 호버한 대상 옆에 뜨고**(고정 위치 없음), 측정 패널은
일시정지 중에만 레인 위에 표시된다. **성벽 패널은 없다 — 성벽 자체가 구매처다**: 클릭 = 수리,
우클릭 = 최대 HP 업그레이드, 가격·회복량은 성벽 호버 상세에서만. — 3차 개편(사용자 확정):
리롤 왼쪽 이동 · 정사각 슬롯 5+5 · 인접 호버 상세 · 성벽 클릭 수리 · 성벽 패널 제거.
근거는 발라트로(보유물 아이콘 + 인접 툴팁)·StS(유물 줄)·TFT(리롤 왼쪽) 문법.
(업그레이드=우클릭은 프로토가 고른 임시 조작이다 — 본편 조작은 미정)

| 조작 | |
|---|---|
| 병사카드 → **빈 칸이나 같은 유닛의 칸** | 구매. 같은 유닛이면 **마릿수가 합쳐진다** |
| 배치된 부대를 **격자 밖으로** 드래그 | 부대를 **뺀다** (환불 없음) |
| 유물카드 → 유물 슬롯 줄로 드래그 | 구매. 유물은 칸에 붙지 않는다 |
| 배치된 부대끼리 드래그 | 자리 교체 (즉시·무료) |
| 부대·보스·매대 카드·유물·예고 슬롯에 **호버** | 오른쪽 아래에 **상세 카드**가 뜬다 |
| 같은 것을 **클릭** | 상세 카드 고정(핀). `[Esc]`로 해제 |
| `[Space]` | 일시정지 — **정지 중 모든 입력 차단** (설계 규칙 그대로) |
| `[S]` | 스폰 모드 전환 (고정 스케줄 ↔ 킬 연동) |
| `[R]` | 재시작 (배속 기능은 3차에서 제거 — 사용자 확정) |

드래그 중에는 놓을 수 있는 칸이 **초록**으로, 만석이라 초과분이 사라질 칸이 **노랑**으로 밝혀진다.
다른 유닛이 선 칸은 아예 밝히지 않는다 — 드롭 전에 결과가 보여야 한다.

## 만든 것

- **무정지 실시간.** 라운드 없음. 적이 스케줄대로 계속 오고, 그 위에서 전부를 판단한다
- **체급 3단 — 소형 · 중형 · 대형.** 체급이 **타격당 딜과 인원 상한**을 정한다(1:3:9 ↔ 9:3:1).
  **인원으로 나누지 않는다** — 상한까지 채운 부대의 총 화력은 체급이 달라도 같고, 체급이 정하는
  것은 "이 보스에게 통하는가"뿐이다. "제때 잡는가"는 인원 × 주기가 답한다
- **체급 배정은 읽어온다.** `sprite_catalog.csv`의 `size_tier`(실측 픽셀)가 체급이고,
  `units.csv`의 `crew`가 인원 상한이다. 둘이 어긋나면 경고를 띄우고 CSV를 믿는다
- **병사카드 = 병사 묶음.** 카드마다 마릿수가 다르고(소형 2~4 / 중형 1~2 / 대형 1),
  같은 유닛의 칸에 부으면 합쳐져 상한까지 자란다. **상한 초과분은 사라진다.**
  칸을 다른 유닛으로 바꾸려면 **먼저 빼내야** 한다
- **가격 = 마릿수 × 체급 단가** (소형 5 / 중형 16 / 대형 54). 대형은 어느 보스에게도 딜 0이
  잘 안 나는 안전 자산이라 단가에 프리미엄이 붙는다
- **물리는 뺀다.** 타격당 딜에서 보스 방어력을 뺀다. **최소 보장은 없다 — 못 넘기면 0이다**
- **명중 판정은 물리에만 있다. 마법은 무조건 적중한다.** 보스의 **회피**가 대응 축이다.
  **빗나감 = 0** — 「미결」의 한쪽 극단을 골라 태운 것이다
- **마법은 곱한다.** 원소 저항값을 그대로 감소율로 쓰고(디아블로식) 상한 `RES_CAP`(임시 75%)을 둔다
- **캐스터도 인원 축을 탄다 — 인원수가 곧 시전 횟수다.** 소형 마법사는 작은 마법을 아홉 번,
  중형은 굵게 세 번 시전한다. 사제가 `ALLY_RANDOM`이면 시전마다 대상을 다시 굴리므로
  **소형 사제는 얇은 축복을 여러 칸에 흩고 중형 사제는 굵게 몇 칸에 건다** — 같은 규칙에서 갈린다
- **원소 4종**(냉기·화염·독·번개). 저항 하나가 두 일을 한다 — 그 원소 피해의 감소율이면서
  그 원소 상태이상의 저항이다
- **적 = 베이스 + 접두사 굴림.** 진영 베이스 21종에 **접두사 11종**(중장갑·경화·원소 강화 4·
  질주·완고·광폭·재생·주박)을 굴려 얹는다. **막보스는 굴리지 않는다 — 조합이 고정이다**
- **4막 구조.** 막마다 진영이 통째로 바뀐다 — 1 오크(저방어·접두사 1개, **중장갑 없음**) /
  2 야수·놀(질주 + 중장갑 혼재) / 3 할로윈(재생·주박) / 4 심연(원소 강화 4갈래).
  막이 넘어갈수록 **스폰 간격이 좁아진다** — 난이도를 스탯이 아니라 쇼핑 시간으로 조인다.
  스탯 인플레는 막보스에만 건다
- **보스의 병력 디버프(주박).** 적은 병력을 때리지 못하지만 성능은 떨어뜨린다. 일시적이고
  누적되지 않으며, **인원이 많은 부대일수록 덜 흔들린다**(머릿수가 완충재). 사제의 `CLEANSE`가
  이걸 정화한다 — 1차 개조 때 "정화할 것이 없어 빈 캐스팅"이던 스킬에 드디어 할 일이 생겼다
- **캐릭터 위에는 이름만 둔다.** 격자 칸에는 부대 이름, 보스 위에는 이름과 **접두사**
  (`질주 · 화염 강화`). 스펙은 전부 상세 카드로 갔다
- **매대 카드 얼굴도 최소로 걷어냈다** (3차 · 사용자 확정 — "정보가 너무 많다, 호버로").
  병사카드 = 실루엣 · 이름 · ×마릿수 · 종족·직업 · 사전 판정 칩(통함/딜 0 · 원소 저항) · 가격.
  유물 = 이름 · 등급 · 태그(받는 칸) · 유니크 동사 한 단어. 전술 = 이름 · 종류·등급 · 얼굴 그림.
  박자·스킬·옵션 줄·효과 텍스트·유래·계산 과정은 전부 호버 상세로 이동 — 기획 「상점」의
  "그림이 먼저, 상세는 호버" 문법에 프로토를 맞춘 것이다
- **상세 카드.** 카드 안에서 `13.8 - 방 6 = 7.8` 처럼 감산 과정이 그대로 보이고,
  마법은 `번개 저항 48% → 98`. 딜 0인 칸은 그 줄이 붉게 뜬다. 접두사는 **막는 것 → 답**을
  그대로 적는다(`중장갑: 다수 물리 전원이 딜 0 → 마법 / 소수정예`)
- **통함 / 딜 0 사전 표시는 매대 병사카드에 남는다.** 타격당 딜을 체급이 고정하므로,
  **부대를 채운 뒤에도 이 표시가 거짓말하지 않는다**
- **직업 리듬 7종** — 확률(전사·소드마스터) / 크리(궁수·암살자) / 캐스팅(마법사·사제).
  유닛 고유 스킬 20종·effect 17종을 `units.csv`·`skills.csv`에서 읽는다
- **크리티컬은 모든 유닛의 공통 스탯이다.** 기본 0이라 공급원이 있어야 터지고,
  궁수·암살자는 직업 자체가 공급원이라 크리가 곧 스킬 발동이 된다
- **유물 = 옵션이 붙은 물건.** 전역 보유(4슬롯). **등급이 옵션 줄 수를**(일반 1 / 매직 2 /
  레어 4 / 유니크 고정), **태그가 옵션을 받을 부대를** 정한다([직업]·[종족]·[전체]).
  태그는 유물 하나에 하나뿐이고 **베이스(형상)가 고정한다** — 굴려지지 않는다.
  **태그가 좁을수록 수치가 크다**(×1.6 / ×1.3 / ×1.0) — 몰빵의 보상이 여기서 나온다.
  매직·레어의 옵션은 접두사·접미사로 굴려지고, **성장형 옵션은 킬마다 누적된다**
- **동사(상태이상·밀어내기)는 유니크에만 붙였다** — 「유물이 스킬을 주는지」 3안 중 (2)번.
  쿨다운이 초도 박자도 아니라 **타격 수로 찬다** — 스택이 타격마다 붙으므로
  **인원이 곧 발동 속도**가 된다. 소형(한 박자에 9타)에선 잦고 작게, 대형(1타)에선 드물고 크게
- **전술카드 세 종류 — 칸 · 골드 · 규칙.** 전용 슬롯 줄(3칸)에 드래그해 놓는다.
  「칸」은 3×3에 칠한 칸 위 부대만 받고, 「골드」는 경제를, 「규칙」은 게임의 기본 규칙 자체를
  바꾼다. **직업·종족은 종류가 아니라 조건절이다** — 조건에 맞는 부대가 많을수록 저절로 세진다.
  시너지를 세는 시스템도, 카운트 UI도 없다. 카드마다 **역사 유래 한 줄**이 붙는다
- **전술카드 목록은 `tactic_cards.csv`에서 읽는다** (3차). 종류·등급·칠하는 칸 패턴·텍스트 키가
  카탈로그에서 오고, 이름·설명·유래는 `text.csv`의 키로 잇는다 — 카탈로그 16종 전부가 돈다.
  **효과의 내용·수치·가격은 미결이라** 프로토의 `TACTIC_FX` 글루가 임시로 얹는다.
  칸나이(중앙 비움)·청야유인(모서리 비움)의 **"비어 있어야 하는 칸"** 조건이 들어갔고,
  카드 얼굴의 3×3에 붉은 칸으로 표시된다. 골드·규칙 카드에는 기획의 **공통 상세 표기**
  (영향 칸 3×3 — 전 부대면 9칸, 경제면 빈 그림)가 붙는다.
  카탈로그 밖 실험 카드 3장이 남아 있다 — 필룸·팔랑크스(규칙 채택 미정 후보), 아쟁쿠르(조건절)
- **상태이상 9종** · **최근접 타게팅** · **겹침** · **밀어내기 저항의 시간 상승**
- **5슬롯 매대** — 첫 매대는 병사카드로만, **킬은 매대를 갱신하지 않는다**(리롤가만 원가 복귀),
  구매한 슬롯은 다음 리롤까지 빈 채
- **성벽** — 런 전체를 관통하는 단일 지속 자원. 매대 밖 고정 패널에서 수리/최대HP 업그레이드
- **칸별 기여도** — 누적 딜과 비율 막대

### 수치를 다시 잡아야 한다 (그대로 남음)

- [ ] **유물 상한이 찼을 때의 교체·처분** — 규칙이 「미결」이라 4칸 차면 더 못 산다. 전술 슬롯도 같다
- [ ] **일반 유물을 재료로 쓰는 것** — 「미결」(3안 중 미정)이라 뺐다

### 기획서에 물어봐야 할 것 — **문서에 적지 않았다**

프로토가 부딪혔지만 사용자가 정한 적 없는 것들이다. 확인 없이 `GAME_DESIGN.md`에 넣지 말 것.

- **「로마의 필룸」류 규칙 카드가 감산을 꺼도 되는가.** 「규칙 종류가 건드리는 것」에 기획이
  직접 후보로 적어둔 항목인데, 보장 1.0은 **이 게임의 중심축을 통째로 껐다**(봇 무피해 클리어).
  0.5로 내리면 감산 세계가 유지된다는 것까지 확인했다 — 대가를 붙일지, 0.5로 갈지, 뺄지
- **경화의 상한** (아래 「경화에 상한이 필요했다」 참조)
- **유물이 동사를 주는 형태** — 프로토는 「미결」 3안 중 (2)유니크 전용을 골라 태우는 중이다
- **「파동」이 무엇인가** — 골드 카드 `TC_GOLD_WAVE`의 "파동을 넘길 때마다". 이 게임에 웨이브가
  없어서 프로토는 **킬마다**로 해석해 태웠다. 막 전환일 수도 있다
- **사선진법(`TC_SASUN`)의 효과** — 미결이라 프로토는 타격당 고정값을 임시로 넣었다
- **골드 6종·규칙 2종의 이름** — 실존 전술명 미정. 프로토 임시 이름(사략 허가장·마케도니아의
  병참·제노바의 환전상·개선식의 전리품·용병의 방패삯·푸거가의 금고·봉수의 사슬·비엔나의 돌격)은
  코드에만 있다 — `text.csv`에 넣지 않았다
- **규칙 종류의 등급** — 미결이라 CSV가 비어 있다. 프로토는 희귀(2등급)로 태운다

## 「미결」을 프로토가 임의로 고른 자리

기획서에는 적지 않는다. 프로토가 답을 보려고 한쪽 극단을 골라 태운 것뿐이다.

| 미결 항목 | 프로토가 고른 것 |
|---|---|
| 빗나감이 0인가, 약화된 타격인가 | **0** — 단독(대형)이 한 박자를 통째로 날리는 체감을 보려고 |
| 빼낸 부대의 처리 | **환불 없이 사라진다.** 매대 위에 떨군 것은 오조작으로 보고 무시한다 |
| 병사카드 마릿수의 분포 | 체급별 고정 범위 (소형 2~4 / 중형 1~2 / 대형 1) |
| 보스 디버프가 걸리는 규칙 | **배치된 칸 중 랜덤 하나.** "이 칸이 흔들린다"가 읽혀야 해서 |
| 접두사 조합 규칙 | **원소 강화 둘은 한 놈에 안 붙는다.** 겹치면 그 판의 마법이 통째로 죽는다 |
| 경화가 어디까지 오르는가 | **상한 +14.** 아래 「경화에 상한이 필요했다」 참조 |
| 재배치 | 즉시·무료 (1차 개조와 같음) |
| 「파동」의 뜻 (TC_GOLD_WAVE) | **킬마다.** 이 게임의 파동은 적 하나라고 읽었다 |
| 사선진법의 효과 | 타격당 고정값 (레우크트라의 사선을 이어받음) |
| 규칙 전술카드의 등급 | **희귀(2등급).** CSV의 빈 등급 칸을 이걸로 채워 태운다 |
| 최소 보장(필룸)의 값 | **0.5.** 1.0은 감산을 통째로 꺼서 내렸다 |

### 경화에 상한이 필요했다 — 개조 중에 실제로 나온 것

접두사 「경화」를 상한 없이 "초당 방어력 +n"으로 만들었더니, 4막 막보스전(40~60s)에서
방어력이 계속 올라 **어느 순간 물리 전 편성이 수학적으로 무력화됐다.** 봇 6판 중 5판이
같은 보스에서 죽었고, 죽는 방식이 "못 잡았다"가 아니라 "잡을 수 없게 됐다"였다.

이건 기획이 **엔드리스를 배제한 이유와 같은 문제**다 — *"감산 방어는 적 스탯 인플레와
양립이 안 된다(어느 순간 전 편성이 수학적으로 무력화된다)"*. 런 단위에서 거부한 성질이
한 싸움 안에서 그대로 재현된 셈이라, 상한을 두는 쪽으로 골랐다. 상한값 자체는 미결이다.

> **기획서에는 적지 않았다.** 사용자가 정한 것이 아니라 프로토가 부딪힌 것이라서다.
> 다만 「접두사 조합 규칙」·「보스 방어력·저항이 자기 강화로 오를 때 상한을 넘을 수 있는지」
> 를 정할 때 같이 볼 만한 데이터다.

## 의도적으로 뺀 것

기획에서 **아직 정해지지 않은 것들**이라 넣지 않았다. 지어내서 채우면 프로토가 기획을 앞질러버린다.

- **리더** — 발동이 리더별 개별이고 각자의 조건이 「미결」이다. 매대 풀에서 통째로 뺐다
  (체급 규칙상 "리더는 체급 무관 단독"만 확정이라, 로더는 그 행을 조용히 건너뛴다)
- **사기** — 증감 규칙과 구간 보너스가 정해지지 않았다
- **전술카드** — 세 종류(칸·골드·규칙)만 확정이고 등급·칸 수·효과 풀이 전부 미결이다
- **유물의 등급·태그·옵션** — 유물을 옵션 아이템으로 재정의하는 논의가 「보류」다.
  프로토의 유물은 1차 개조의 "동사 공급원" 모델 그대로다
- **저주 · 저항 감소** — 계산 경로는 살아 있지만 **부여원이 없다**(공급처가 미결)
- **유물 상한이 찼을 때의 교체·처분** — 규칙이 미결이라 4칸이 차면 더 못 산다

그 밖에 프로토 범위 밖이라 뺀 것: 종족 시너지 · 근접 돌진 연출 · 언락 · 밸런싱.

## 스폰 모드 두 가지 — 「미결」 1순위를 직접 태운 것

| 모드 | 규칙 |
|---|---|
| **고정 스케줄** | 스폰 시각이 절대적. 빨리 잡으면 그만큼 온전히 논다 |
| **킬 연동** | 킬하면 3.5초 뒤 다음 한 마리를 당겨온다. 스케줄은 상한으로만 남는다 |

## 헤드리스 검증

`_smoke.gd`는 무입력 실행으로는 안 타는 경로(드래그 구매·**합류**·**빼내기**·유물 구매·
자리 교체·패널 구매·무효 드롭)를 강제로 태우는 임시 봇이다.

```
godot --path . --headless --fixed-fps 60 --script prototypes/realtime_defense/_smoke.gd
godot --path . --headless --fixed-fps 60 --script prototypes/realtime_defense/_smoke.gd -- adaptive
godot --path . --fixed-fps 60 --script prototypes/realtime_defense/_smoke.gd -- shots=<폴더>   # 스크린샷
```

> 처음 받은 저장소라면 스프라이트 임포트 캐시가 없어 실패한다. `godot --headless --path . --import`
> 를 한 번 돌린 뒤 실행한다.

### 경로 검증 (둘 다 통과)

```
배치 9/9 · 인원 9/43  →  채움 후 인원 43/43     (합류제가 상한까지 찬다)
다른 유닛 칸 거부: true                          (취소·무과금)
만석 초과분 소멸: true
빼내기 후 배치 0/9                               (격자 밖 드래그 = 해체)
잘못된 목적지 무과금: true
스킬 발동(effect별 17종) — 17종 전부 발동
킬 시 매대 유지 12회 / 갈림 0회                   (강제 갱신 없음이 지켜진다)
```

### 봇 실행 결과

**사람 손이 아니다.** 무한 골드로 9칸을 즉시 상한까지 채우고 중간에 한 번만 갈아엎는
고정 편성이며, 매대를 보지도 리롤하지도 않는다. 게다가 그 편성에 사제가 셋이라 직접 딜이
없는 칸이 셋이다. **밸런스 판정이 아니라 기전 확인용이다.**

접두사를 매번 굴리므로 판마다 갈린다 — 모드당 3판씩 돌린 범위다.

| | 고정 스케줄 (3판) | 킬 연동 (3판) |
|---|---|---|
| 결과 | 패배 11/12 × 3 | **클리어 12/12 × 2** · 패배 11/12 × 1 |
| 경과 | 192~198s | 198~204s |
| 평균 처치 소요 | 12.0~12.7s | 9.4~13.4s |
| 최대 겹침 | 3~4마리 | 1마리 |
| 딜 0 타격 비율 | 47~56% | 55~57% |
| 빗나감 비율 | 5~10% | 7~8% |
| 물리 감산 손실 | 58~65% | 65~67% |

**지는 곳이 항상 같다 — 4막 막보스(흑룡)다.** 중장갑·경화·화염 강화·완고가 겹친 놈이라,
매대를 한 번도 안 본 고정 편성으로는 답이 모자란다. 막보스가 "그 막이 요구한 답을 다
갖췄는지를 묻는다"는 자리인 것을 감안하면 이 자체는 기전대로다 — 다만 **사람이 쇼핑했을 때
실제로 답이 손에 들어오는지**는 이 봇이 답할 수 없는 질문이라 플레이로 확인해야 한다.

> **3차(필룸 0.5 · CSV 전술카드) 재실행:** 고정 2판 = 패배 11/12 · 클리어 12/12(성벽 324),
> 킬 연동 1판 = 클리어 12/12(무피해, 흑룡 50s). 감산 손실 58~62%로 2차 밴드 안이고,
> 흑룡 벽은 접두사 굴림·크리 운에 따라 판마다 갈린다 — 보장 1.0 때의 "전판 무피해"는 없다.

### 여기서 실제로 보이는 것

- **감산 세계가 유지된다.** 딜 0 타격 47~57%는 1차 개조의 31~76% 밴드 안이다.
  체급을 3단으로 끊어도 "물리에 면역이 자연 발생한다"는 성질이 그대로 살아 있다
- **겹침이 눈덩이로 작동한다.** 고정 스케줄에서 후반 처치 소요가 길어지자 레인에 3~4마리가
  쌓이고 그대로 성벽이 무너졌다. 킬 연동 쪽은 세 판 모두 겹침이 1마리로 유지됐다 —
  **강한 편성일수록 런이 짧아진다**는 1차 개조의 결론과 방향이 같다
- **캐스터의 인원 축이 세다.** 마법사 두 칸이 누적 딜의 상위를 차지한다. 마법은 비율이라
  방어력을 안 타는데 인원만큼 시전하므로, 물리가 감산에 절반 넘게 먹히는 구간에서 격차가 벌어진다.
  기획이 "마법은 체급 곡선에서 벗어난다"를 성격으로 두기로 했으니 결함은 아니지만,
  **수치로 눌러야 하는 지점이 어디인지**가 여기서 보인다
- **1막에서 「두 단계」가 안 선다.** 봇 기준 1막 정예의 처치 소요가 2~7s인데 접근 시간은 19s라,
  성벽에 닿기 전에 죽는다. 「접근 중 → 성벽 타격 중」이 성립하지 않는다. 다만 봇은 무한 골드로
  9칸을 즉시 만석으로 채운 상태이고 **실제 1막 플레이어는 한두 칸뿐**이라, 이것이 설계 문제인지
  봇의 인공물인지는 사람 손으로 확인해야 안다

### 수치는 전부 임시값이다

2차 개조에서 데미지 모델이 뒤집히면서(총 화력이 인원에 비례) 기존 수치가 전부 무의미해졌다.
봇을 돌려가며 "교전이 접근 시간과 비슷한 길이가 되는" 선까지만 맞췄다 — 밸런싱이 아니라
**프로토가 답하려는 질문을 물을 수 있는 상태로 만든 것**이다.

## 확인해볼 것

| | 무엇을 보는가 |
|---|---|
| **부대 채우기** | 같은 유닛 카드를 기다리게 되는가, 아니면 빈 칸을 먼저 채우게 되는가 |
| **만석 초과** | 노란 표시를 보고 멈추는가, 아니면 그냥 붓는가 |
| **빼내기** | 칸을 갈아엎는 판단이 실제로 생기는가. 환불 없음이 너무 무거운가 |
| **체급 세 단어** | "소형/중형/대형"이 매대에서 한 단어로 통하는가 |
| **소형 vs 대형** | 물량 투자형과 즉전력 중 어느 쪽으로 손이 가는가 |
| 첫 정예 두세 마리 | 전투를 보면서 카드를 읽고 살 수 있는가 |
| 겹쳤을 때 | 두 마리가 되면 회복하려 드는가, 그냥 포기하게 되는가 |
| **접두사** | `질주 · 화염 강화` 몇 단어로 대응이 정해지는가 |
| **막 전환** | 진영이 바뀌는 것이 진행 실감으로 읽히는가 |
| **막보스 고정** | 무엇이 기다리는지 알고 쇼핑하게 되는가 |
| **빗나감 = 0** | 대형·단독이 한 박자를 통째로 날리는 것이 억울한가, 긴장인가 |
| **주박** | 인원이 완충재라는 것이 체감되는가. 정화(네크로맨서)를 찾게 되는가 |
| **경화** | 시간이 갈수록 방어력이 오르는 것이 "빨리 잡아야 한다"로 읽히는가 |
| 매대의 통함 / 딜 0 | 감산 결과를 보고 구매를 실제로 바꾸는가 |
| 유물 자동 발동 | 인원이 많은 칸에서 더 자주 터지는 것이 보이는가 |
| 성벽 패널 | 카드와 수리 사이에서 갈등이 생기는가 |
| `[S]` 두 모드 | 어느 쪽이 "킬 속도가 여유를 산다"로 느껴지는가 |

**핵심 체크:** 위의 어느 하나라도 "볼 틈이 없다"로 답이 나오면 실시간 전제가 흔들린다. 그때
고칠 곳은 UI가 아니라 **스폰 스케줄**이다.
